# Клинично съдържание

Тази папка съдържа **данните**, не кода: колко секунди трае издишването, какво точно
чува човек по време на заземяване, коя е следващата стъпка в експозицията, кой не бива да
прави дадено упражнение и какво прави приложението при тревожен запис в дневника.

Разделението между механизъм и съдържание е нарочно и е основата на целия план. Кодът се
пише преди психологът да е казал дума; одобреното съдържание влиза после, без да се пипа
код.

---

## Правилото

> **Нищо от тази папка не влиза в релийз без писмено одобрение от квалифициран
> специалист.**

Без изключения. Без „временно, докато чакаме“. Ако одобрението се забави, излиза версия
**без** съответната част — не версия с неодобрени стойности.

Причината не е бюрокрация. Интероцептивната експозиция е ефективна, но при неправилно
самостоятелно прилагане може да **засили** паниката. Дихателен протокол с грешни числа е
безполезен в най-добрия случай. Grounding скрипт с грешна формулировка може да звучи като
омаловажаване точно в момента, в който човекът е най-уязвим.

## Форматът

Версионирани JSON файлове. Схемата е в
[`schema/protocol.schema.json`](schema/protocol.schema.json), а описанието на самите
параметри — в [docs/ДИШАНЕ.md](../docs/ДИШАНЕ.md).

```
clinical/
  schema/      договорът — какво приема енджинът
  protocols/   одобреното, което се пуска
  examples/    чернови и запълващи стойности; никога в релийз
```

Всеки файл носи задължително `id`, `version`, `kind`, `status` и `approval`.

**Одобрението е на конкретна версия.** Полето `approval.appliesToVersion` трябва да съвпада с
`version` на файла. Смениш ли една стойност, вдигаш версията и старото одобрение спира да
важи — точно това е смисълът му. Одобрява се файл, не „протоколът“ по принцип.

```json
"approval": {
  "approvedBy": { "name": "…", "credentials": "…", "registration": "…" },
  "approvedAt": "2026-09-01",
  "appliesToVersion": 3,
  "scope": "за какво точно важи това одобрение",
  "reviewDue": "2027-09-01"
}
```

**Границите в схемата са механични, не клинични.** Те са граници на енджина и хващат явна
грешка — изтървана запетая, секунди, записани като милисекунди, файл, редактиран на ръка.
Не заместват клиничната преценка и не твърдят нищо за това кое е правилно.

## Проверката

```
python tools/validate_clinical.py            # схема, съгласуваност, дублирани id
python tools/validate_clinical.py --release  # плюс: отказва всичко неодобрено
```

Без външни зависимости. Връща изходен код 1 при поне една грешка, за да спре билда
(задачи 3.7 и 4.1) и да не разчита на човешка памет в пет без пет преди пускане.

Режимът за релийз отказва всеки файл в `protocols/` без писмено одобрение. **Празната папка
минава** — приложението се пуска без съответната част. Неодобрен протокол не минава.
